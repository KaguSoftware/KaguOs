05HOW TO ACTUALLY LEARN THIS

At this level, nothing counts until it runs twice. Build inside a real project, and prove every technique with an output you can re-run — not a screenshot.

70 / 30
Build it live

70% of your time inside a real project wiring things up, 30% watching or reading.

RUN TWICE
Twice or it doesn't count

A result that worked once is a demo. Re-run it on new inputs before you believe it.

STEAL IT
Steal the prompt & eval

When a video shows a prompt or an eval, rebuild your own version on your own data now.

GATE IT
Cheap gates beat hope

Add the smallest verification that would catch the failure you fear most.

VERSION
Treat prompts like code

Version every working prompt so you can improve it without silently breaking it.

SHIP IT
Ship the system

A reusable system shipped by day 13 beats a perfect one you never finish.

06THE CAPSTONE

A system that works once is a demo. A system that works twice is a tool. Building one — with an eval that proves it — touches skills, structure, context, and verification all at once. That's why it's the proof.

What passes — tick each
  • Pick a repeatable job you actually do
  • Build it as a skill, template, or agent (parameterized)
  • Write a 5-case eval set that defines "correct"
  • Run it 3× — same inputs, same quality
  • Add one cheap verification gate
  • Version it so you can improve without breaking it
Build timeline
  • D13Build the system and its 5-case eval set
  • D14Run it 3×, add the verification gate, version and ship
